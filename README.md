# mcd-kids-guardian · 麦麦家长助手

> 一个基于麦当劳 MCP（mcd-mcp）的儿童营养守护点餐 Skill。
> 给 3-12 岁孩子的家长一句能直接照做的话：**这一餐点什么，孩子开心、营养够、钱也不多花。**

## 为什么需要它

成人看麦当劳是「热量炸弹」，孩子看麦当劳是「开心乐园」。家长真正纠结的不是「能不能吃」，而是三个同时成立的问题：

1. **营养够不够** —— 这一餐热量、钠、蛋白质有没有落在同龄区间；
2. **孩子买不买账** —— 没有薯条/玩具/麦乐鸡的组合，孩子不吃等于白搭；
3. **钱花得值不值** —— 同样的营养，能不能挑到更便宜、还能叠券的那个。

市面上两类工具都只解决一半：营养 App 只报数字不懂点餐，点餐工具只管下单不问营养。本项目把**营养阈值表 + 真实门店菜单 + 优惠券算价**缝在一起，输出一张家长当场能用的卡片。

## 它能做什么

| 能力 | 实现 |
|---|---|
| 按年龄查营养硬标准 | 3/4-6/7-10/11-12 四档：热量区间、钠上限、蛋白质下限 |
| 定位真实门店 | `query-nearby-stores`（收藏优先，失败转「城市+地标」） |
| 拆真实套餐组件 | `query-meal-detail` 解析 rounds，取 `isDefault=1` 的默认搭配 |
| 逐组件核算 | `scripts/combo_evaluator.py` 确定性求和，杜绝口算 |
| 占每日建议百分比 | 中国居民膳食营养素参考摄入量 + WHO 儿童钠建议折算 |
| 券后实付价 | `query-store-coupons` + `calculate-price`（只算价，不下单） |
| 诚实降级 | 全超钠/热量不足/无营养数据时，明说并给「最接近达标」方案 |

## 用一次看看

```
家长：我儿子 8 岁，不吃辣，我在沈阳铁西龙之梦，想给他点麦当劳
助手：（问齐年龄/性别/忌口/位置后）
      → 定位门店 → 拉菜单 → 拆套餐 → 跑核算脚本 → 查券 → 算价
      → 3 张卡片：鱼排堡 ¥24（三项达标）/ 汉堡 ¥23.5（最便宜）/ 麦乐鸡 ¥25（钠最低但需补热量）
```

## 命令速查

```bash
# 单组合核算（人读）
python scripts/combo_evaluator.py --age 8 --gender 男 --restrict 不吃辣 \
    --items "汉堡包 x1, 迷你薯条 x1, 苹果片一袋(60g) x1, 纯牛奶(盒装) x1" --price 23.5

# 机读 JSON（接卡片渲染/批量评估）
python scripts/combo_evaluator.py --age 8 --json --items "麦乐鸡4块 x1, 纯牛奶(盒装) x1"

# 低钠排行
python scripts/sodium_ranking.py --menu meals.json --top 20

# 回归自测（改完任何阈值/别名后必跑）
python scripts/selftest.py
```

## 验收用例

`scripts/selftest.py` 覆盖 8 条断言，当前 **8/8 通过**：

| 用例 | 期望 |
|---|---|
| 7-10 鱼排堡餐 | 536/576/24，三项达标 |
| 7-10 汉堡餐 | 515/626/22，三项达标 |
| 7-10 麦乐鸡餐 | 384 kcal 低于下限 → 不可推荐为常规 |
| 4-6 同一份麦乐鸡餐 | 384 落入 350-500 → 达标（证明阈值分档生效） |
| 双层吉士汉堡+中薯条+可乐 | 865 kcal / 1182 mg，钠与热量双超，触发降级提示 |
| 含「龙焰鸡腿堡」 | 报「无数据」，不估算、不模糊匹配 |
| 「苹果片一袋(60g)」 | 经别名表折算为「苹果片」并声明假设 |
| 3 岁 | 借用 4-6 岁表并附儿保提示 |

## 三个设计取舍（也是这个 Skill 的立场）

1. **宁可少推一个，不可错安一个数据。** 名称对不上就报「无数据」，绝不做模糊匹配。曾出现「龙焰鸡腿堡」被模糊匹配到「板烧鸡腿堡」的事故——在儿童营养场景，静默错数比拒答危险得多。
2. **热量低于下限同样不达标。** 很多工具只防「吃太多」，但 8 岁孩子一餐 384 kcal 撑不到下一顿。本 Skill 对热量做区间双向判定，低了也要给补位动作。
3. **只算价，不下单。** 所有消费类工具（create-order / draw-lottery / auto-bind-coupons）一律禁用。这是「建议」和「替家长做决定」的分界线。

## 数据来源与时效

| 数据 | 来源 | 时效 |
|---|---|---|
| 菜单与价格 | `query-meals`（单位：元） | 实时 |
| 营养值 | 麦当劳官方营养库，快照 158 项 | 2026-10-18 拉取 |
| 实付价 | `calculate-price`（单位：分） | 实时 |
| 优惠券 | `query-store-coupons` | 实时 |

营养快照超过 90 天，或遇到缺失单品时，用 `list-nutrition-foods` 重新拉取并覆盖 `references/nutrition-data.json`（字段：name / kcal / protein / fat / carb / sodium / calcium）。

## 局限（诚实声明）

- **只覆盖麦当劳**，且只在返回了营养数据的单品上核算；新品往往滞后于菜单。
- **不替代医学建议**：本 Skill 的钠/蛋白质阈值按大众儿童膳食参考折算，过敏、慢性病、生长发育异常请遵医嘱。
- **交叉污染无法排除**：麦当劳共用生产线与烹炸油，过敏儿童必须到店与店员确认。
- **规格歧义**：菜单写「薯条」「纯牛奶」时不带杯型/盒型，Skill 按别名表取默认规格并标注，必要时会反问家长。

## 后续可做

- 双人份（家长 + 孩子）联合核算，避免家长那份把钠预算吃光；

- 营养快照自动刷新脚本（超 90 天提醒 + 一键覆盖）。
